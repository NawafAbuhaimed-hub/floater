# Taste, for anything with a screen

Only applies when the task touches UI. Skip it otherwise.

## Defaults are the enemy

The tells of unconsidered work: a 1px grey border on every card, a purple-blue
gradient hero, three font sizes that are all 14-16px, shadows under everything,
`border-radius: 8px` everywhere, emoji standing in for icons. If the work could
belong to any product, it belongs to none.

## Hierarchy before decoration

One thing per screen should be obviously the most important. Achieve it with
size, weight and space — not with colour and borders. If everything is
emphasised, nothing is.

## Spacing is the design

Use one scale and stay on it. Related things sit closer together than unrelated
things; most cramped interfaces are a spacing problem, not a layout problem.

## Type

Two weights and three sizes carry almost any interface. Set line height by the
line's length. Numbers that are compared should be tabular and aligned.

## Colour

One accent, used for the single most important action. Everything else is
neutral. Semantic colour (error, warning, success) is reserved for meaning,
never for decoration.

## Motion

Motion explains a change — where something came from, what became what. It
should be fast enough to feel instant: 150-250ms. Anything that animates on
every render is noise.

## Respect the existing system

If the project has a design system document, it outranks everything here.
Follow it, and say so in the prompt.

## States are not optional

Empty, loading, error and too-much-content are part of the design, not
afterthoughts. An interface that only works with three perfect rows is not
finished.
